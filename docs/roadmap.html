تیم و زمان‌بندی واقع‌بینانه

تیم پیشنهادی (۱۶ هفته)
  • یک توسعه‌دهندهٔ فول‌استک — Next.js + Postgres؛ صاحب فرانت و API
  • یک توسعه‌دهندهٔ بک‌اند/دیتا — worker ها، ingest، اسکرپرهای رگولاتور
  • یک نفر محتوا و دیتا — ورود ۴۲ بروکر، مقالات، روش‌شناسی، مدیریت انجمن از فاز ۳
  • طراحی: انجام شده — توکن‌ها در design-web/README.md
اگر تنها هستید
  • همین ترتیب فازها، ولی ۲۴ هفته — نه ۱۶
  • فاز ۲ را نصف کنید: اول فقط CoinGecko و تقویم؛ رگولاتور واچر و رادار میم‌کوین بعد از انتشار
  • فاز ۳ را به «نظر + گزارش وضعیت» محدود کنید؛ سیگنال و لیدربورد بعد از انتشار
  • ورود دیتای بروکرها را برون‌سپاری کنید — ۴۲ بروکر × ۴۰ فیلد، کار یک هفتهٔ تمام است
⏱
قاعدهٔ زمان‌بندی: هر فاز یک «تعریف تمام‌شدن» (DoD) دارد. تا DoD پاس نشود، فاز بعد شروع نمی‌شود — حتی اگر تقویم بگوید وقتش است. این تنها راه جلوگیری از انتشار چیزی است که نصفه کار می‌کند.

جریان داده:
منابع خارجی ──▶ worker (ingest) ──▶ Postgres/Timescale ──▶ web (RSC + ISR) ──▶ کاربر
                                  └──▶ Redis (کش، pub/sub) ──▶ ویجت‌های زنده

دیتای زنده و اعتماد

هدف: هر عددی که «زنده» ادعا می‌شود، تایم‌استمپ و منبع داشته باشد
هفتهٔ 6–8

محصول

  • فرمول امتیاز ۶ مؤلفه‌ای قفل شد — وزن‌ها در packages/core/src/score.ts
  • فرمول رادار ریسک (وزن تقویم، آنلاک، انقضا، فاندینگ) — مستند
  • لیست رگولاتورهای مانیتور و درجهٔ A/B/C
  • آستانهٔ ایندکس میم‌کوین (نقدینگی ≥ $10K)

فرانت

  • هزینهٔ کل (اسپرد + کمیسیون) در یک عدد، با تاریخ آخرین بازبینی
  • نقشهٔ Entity با انتخاب کشور (کوکی برای یادآوری)
  • نشان وضعیت ۲۴ ساعته (فعلاً از دیتای رگولاتور و آپ‌تایم)
  • رادار میم‌کوین با چیپ‌های امنیت و سورت
  • تقویم اقتصادی + شمارش معکوس + تفسیر یک‌خطی
  • رادار ریسک در هوم؛ لاگ تغییر قوانین پراپ؛ فید آلرت رگولاتور

بک‌اند

  • هزینهٔ اعلام‌شده: بازبینی ماهانهٔ صفحات شرایط بروکرها در ادمین؛ هر فیلد تأییدنشده در سایت برچسب می‌خورد
  • رگولاتور واچر: Playwright روزانه ۵ رجیستری → snapshot → diff → regulator_alerts
  • پراپ رول ترکر: fetch + normalize + diff هفتگی
  • میم‌کوین: GeckoTerminal new pools هر ۵ دقیقه → GoPlus → امتیاز امنیت
  • تقویم: برنامهٔ انتشار رسمی BLS/Fed/ECB به‌صورت seed + مقادیر واقعی از FRED (رایگان)
  • رادار ریسک: cron ساعتی؛ Deribit برای انقضا؛ DefiLlama برای آنلاک
  • هر ingest → ingest_runs؛ آلرت به تلگرام مدیر اگر ۲ اجرا پشت هم fail

ادمین

  • داشبورد سلامت دیتا: هر منبع، آخرین اجرا، تازگی، خطاها، نمودار
  • override دستی: entity mapping، امتیاز، وضعیت بروکر
  • صف بازبینی آلرت رگولاتور → تأیید → انتشار خودکار خبر
  • صف بازبینی هزینه: کدام بروکر بیش از ۳۰ روز بازبینی نشده
  • ویرایش دستی رویداد تقویم و تفسیرش

جامعه

هدف: محتوای کاربر شروع شود — نظر تأییدشده، گزارش وضعیت، سیگنال امتیازدار
هفتهٔ 9–11

محصول

  • قوانین انجمن، سیاست حذف نظر (فقط نقض قوانین — هرگز درخواست بروکر)
  • فرآیند claim بروکر: ایمیل دامنهٔ رسمی + مدرک
  • دیسکلیمر سیگنال؛ ممنوعیت واژه‌های «تضمین»، «قطعی»
  • دعوت ۲۰ کاربر اولیه از گروه‌های تریدینگ برای seed نظرات

فرانت

  • ثبت‌نام/ورود (OTP)، پروفایل عمومی، تنظیمات
  • فرم نظر + آپلود استیتمنت + نشان تأیید
  • گزارش وضعیت یک‌کلیکی (تأخیر برداشت / قطعی / اسلیپیج) → نمودار ۲۴h
  • کامنت روی بروکر، کوین، رویداد، مقاله (threaded)
  • فرم سیگنال ساختاریافته؛ فید؛ لیدربورد؛ پروفایل تریدر با آمار
  • پاسخ رسمی بروکر زیر نظرات؛ نشان «پروفایل رسمی»

بک‌اند

  • نقش‌ها و مجوزها (RBAC) در middleware
  • استیتمنت: آپلود → R2 → worker: OCR (tesseract) + regex حذف شمارهٔ حساب و نام → نشان → حذف فایل بعد ۲۴ ساعت
  • گزارش وضعیت: rate limit (IP + user + broker)، تجمیع ۲۴h/۷d، آستانهٔ تغییر وضعیت (مثلاً ≥۱۰ گزارش مستقل)
  • سیگنال: schema سخت (zod)، immutable، worker هر ۱ دقیقه: TP/SL touch با فید قیمت → outcome → R → آمار تریدر؛ لیدربورد با حداقل ۳۰ سیگنال
  • ضد اسپم: Turnstile، rate limit، لینک nofollow، فیلتر کلمات، shadow-ban
  • نوتیفیکیشن درون‌سایتی (پاسخ، فالو)

ادمین

  • صف مدیریت واحد: نظر، کامنت، گزارش، سیگنال — با تأیید/رد/ویرایش/بن یک‌کلیکی
  • بازبینی استیتمنت (تصویر ماسک‌شده) → تأیید نشان
  • تأیید claim بروکر؛ مدیریت نمایندگان
  • مدیریت کاربران: نقش، بن، shadow-ban، تاریخچه
  • audit_log برای هر اقدام مدیر — غیرقابل حذف
  • گزارش‌های تکراری/مشکوک (یک IP، چند حساب)
DoD:۱۰۰ نظر تأییدشدهصف مدیریت زیر ۲۴ ساعت خالی می‌شوداولین سیگنال به‌صورت خودکار امتیاز گرفته۳ بروکر پروفایل claim کرده‌اند

  • متن افشا روی هر لینک — نه فقط فوتر
  • پلن Pro: چه چیزی رایگان، چه چیزی پولی (جدول در بلوپرینت)
  • ساختار «صبحانهٔ بازار»: ۵ خط، هر صبح ۷:۰۰ به وقت مخاطب

فرانت

  • دکمه‌های افیلیت با افشا؛ صفحهٔ «کجا بخرم»
  • signup خبرنامه (هوم، مقاله، فوتر) + صفحهٔ آرشیو
  • آلرت: قیمت، اسپرد، خبر، سیگنال تریدر فالوشده — با نام‌پد ماکاپ
  • ویجت‌های امبد: تیکر، تقویم، وضعیت بروکر — صفحهٔ سازندهٔ ویجت
  • صفحهٔ Pro، checkout، مدیریت اشتراک
  • i18n (next-intl): en + fa، hreflang، سوییچ زبان

بک‌اند

  • افیلیت: /go/[id] redirect با click id و geo؛ postback endpoint؛ جدول تبدیل
  • خبرنامه: worker روزانه: جمع دیتای خودمان (رادار، تقویم، آلرت رگولاتور، بهترین سیگنال) → مدل زبانی → پیش‌نویس → تأیید یا ارسال خودکار → Resend + تلگرام
  • آلرت: جدول شرط‌ها → worker هر دقیقه ارزیابی → ایمیل/تلگرام → لاگ تحویل
  • ویجت: endpoint JSON با کش CDN + اسکریپت ۳KB
  • Pro: Stripe checkout + webhook؛ درگاه کریپتو؛ feature flags per user

ادمین

  • مدیریت افیلیت: لینک per بروکر × کشور، نرخ کمیسیون، گزارش کلیک/تبدیل/درآمد
  • ادیتور خبرنامه: پیش‌نویس خودکار، ویرایش، پیش‌نمایش، ارسال، آمار open/click
  • مدیریت پلن‌ها، اشتراک‌ها، کوپن‌ها، ریفاند
  • مدیریت ترجمه‌ها (رشته‌های UI و محتوای دو زبانه)
  • آمار ویجت: کدام سایت‌ها، چند نمایش
DoD:اولین تبدیل افیلیت ثبت‌شده۱۰۰۰ مشترک خبرنامه۵ سایت ویجت را نصب کرده‌اندهر دو زبان بدون رشتهٔ ترجمه‌نشده

چک‌لیست انتشار

سئو
  • ۳۰۰+ صفحهٔ ایندکس‌پذیر با محتوای واقعی؛ thin content → noindex
  • Rich Results Test برای ۵ نوع صفحه پاس
  • sitemap index ثبت در GSC و Bing
  • canonical، hreflang، robots درست
  • OG image برای هر صفحه؛ عنوان و description یکتا
  • صفحات methodology / authors / about / disclosure منتشر
  • لینک داخلی: هر بروکر ↔ مقایسه ↔ مقالات ↔ کوین‌های CFD
پرفورمنس
  • Lighthouse موبایل ≥ ۹۰ (هوم، لیست، بروکر، مقاله)
  • LCP < 2.5s · INP < 200ms · CLS < 0.1
  • JS اولیه < 150KB روی صفحات محتوایی
  • فونت self-host، AVIF، lazy load زیر فولد
  • ISR درست: کوین ۶۰ث، بروکر روزانه + on-demand
امنیت
  • rate limit همهٔ POST ها؛ Turnstile روی فرم‌های عمومی
  • CSP، HSTS، CSRF، secure cookies
  • zod روی هر ورودی؛ اسکن آپلود؛ محدودیت حجم
  • Cloudflare WAF + bot fight
  • کلیدها در secret manager؛ rotation انجام‌شده
  • pnpm audit پاک؛ dependabot فعال
  • تست: SQLi، XSS، IDOR روی endpoint های نوشتن
عملیات
  • Sentry در web/admin/worker با release tracking
  • BetterStack: وب، API، worker heartbeat، ingest تازگی
  • Postgres PITR + R2 versioning + ریستور تست‌شده
  • runbook: قطعی CoinGecko، قطعی VPS اسپرد، حملهٔ اسپم، درخواست حذف بروکر
  • لود تست ۵۰۰ همزمان پاس
  • دامنه، DNS، SSL، ایمیل (SPF/DKIM/DMARC)
حقوقی
  • Terms of Service · Privacy Policy (GDPR-aware)
  • افشای افیلیت — روی هر لینک و صفحهٔ جدا
  • دیسکلیمر ریسک — فوتر و صفحهٔ سیگنال
  • سیاست نظرات و فرآیند اعتراض بروکر
  • سیاست حذف دیتا و استیتمنت (۲۴ ساعت)
  • مشاورهٔ حقوقی برای حوزهٔ قضایی شرکت
محتوا و اعلان
  • ۴۲ بروکر، ۱۷ پراپ، ۲۴ صرافی — بدون فیلد خالی
  • ۲۰ مقالهٔ پایه با نویسندهٔ واقعی
  • ۱۰۰ نظر تأییدشدهٔ seed
  • soft launch ۵۰ نفر → ۱ هفته → رفع
  • اعلان: تلگرام، توییتر، ردیت، Product Hunt (en)
  • outreach ۲۰ سایت/کانال برای ویجت

11

ریسک‌ها و پاسخ

دیتای اعلام‌شده کهنه می‌شود

بروکرها اسپرد و حداقل واریز را بی‌اعلان عوض می‌کنند. پاسخ: هر فیلد یک verifiedAt دارد؛ سایت هر چیزی را که تأیید نشده یا بیش از ۹۰ روز از بازبینی‌اش گذشته علامت می‌زند.

منابع دیتا ToS دارند

API رسمی همیشه بر اسکرپ ارجح است. اسکرپ فقط برای رجیستری رگولاتورها (دیتای عمومی، تناوب روزانه، user-agent شفاف). کش کنید تا سقف‌ها را نزنید.

اسپم و ریویوی جعلی

روز اول شروع می‌شود. پاسخ: نشان تأیید فقط با استیتمنت؛ نظر بدون تأیید در رتبه اثر ندارد؛ Turnstile؛ rate limit؛ shadow-ban؛ تشخیص چند حساب. بودجهٔ مدیریت را از فاز ۳ در نظر بگیرید.

بروکرها فشار می‌آورند

درخواست حذف نظر، تهدید حقوقی. پاسخ: سیاست مکتوب و عمومی: حذف فقط با نقض قوانین. فرآیند claim و پاسخ رسمی. همهٔ رتبه‌ها با فرمول عمومی قابل دفاع.

تأیید افیلیت کند است

بروکرها ۲–۶ هفته برای تأیید پارتنر وقت می‌گیرند. پاسخ: درخواست‌ها را از فاز ۱ بفرستید، نه فاز ۴. با ترافیک واقعی درخواست بدهید.

scope creep

چت زنده، اپ، API — همه جذاب‌اند و همه بعد از انتشارند. پاسخ: DoD هر فاز. هر ایدهٔ جدید به فاز ۶ می‌رود مگر اینکه چیزی را از فاز فعلی حذف کند.

این رودمپ با فرض تیم ۳ نفره نوشته شده. ارقام بودجه تقریبی و بر اساس قیمت‌های عمومی سرویس‌ها در زمان نوشتن است. طراحی‌ها در design/ و design-web/ و بلوپرینت محصول در آرتیفکت جدا.
